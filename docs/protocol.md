# F108Pro 协议摘要

以下格式来自指定版本 Windows 驱动的静态分析，并与 macOS LCD 参考项目、部分有线实机通信交叉核对。无线握手尚未打通，不能将协议编码自检写成实机成功。

## USB 有线接口

VID/PID 为 `0C45:800A`。

| 用途 | Usage | 报文 |
| --- | --- | --- |
| 配置 | `FF13:0001` | Feature / Input 64 bytes |
| LCD 上传 | `FF68:0061` | Output 4096 bytes |

本机配置接口为 interface 3，普通键盘输入在 interface 0。匹配时同时核对 usage 和报文尺寸，不只依赖安装包 XML 的接口字符串。

macOS 使用 Report ID=0 和64字节载荷；Windows 的65字节缓冲区额外包含一个零 Report ID 前缀。

### 校时

按顺序发送：

1. `04 18`，其余清零。
2. `04 28`，offset8=1。
3. 日期时间数据。
4. `04 02`。

时间载荷：

| Offset | 值 |
| --- | --- |
| 1 | 屏幕槽位，当前为1 |
| 2 | `5A` |
| 3 | year−2000 |
| 4–8 | 月、日、24小时时、分、秒，直接二进制数值 |
| 10 | 星期，周日为0 |
| 62–63 | `AA 55` |

其余清零。普通命令应答的 offset3=1；时间数据返回完整回显，其 offset3 是年份，必须分别判断。接收缓冲区预先清零，避免将发送内容误作回显。

### 其他有线命令

| 命令 | 用途 |
| --- | --- |
| `04 13` | 灯光参数块 |
| `04 17` | 系统参数块 |
| `04 11` / `04 27` | 普通层 / Fn层改键表 |
| `04 15` | 宏库数据 |
| `04 23` | 用户逐键 RGB 数据 |
| `04 20` | 实时 RGB 推送 |
| `04 F5` | RGB 查询，读取9个64字节报文 |
| `04 F0` | 恢复已保存灯效 |
| `04 72` | LCD 上传数据头 |

RGB 查询结果不是键位、宏库或完整非易失配置的备份。

### LCD

画布为240×135，RGB565小端，最多141帧。数据包含256字节头与像素帧，以4096字节向上补齐 `FF`。头 offset0 为帧数，offset1 起是各帧的20ms单位延时。

每页必须收到 `01 5A` 应答。Windows 路径使用所选槽位加一，参考 macOS 工具使用 selector=0；当前实现采用后者，仍需实机上传验证。

## 2.4G 接收器

原配接收器产品名为 `F108Pro Dongle`，VID/PID `05AC:024F`。

| 接口 | Usage | Input / Output | 中断端点 |
| --- | --- | --- | --- |
| interface 3 | `FF60:0061` | 32 / 32 bytes | IN `85`、OUT `05` |
| interface 4 | `FF59:0061` | 64 / 64 bytes | IN `86`、OUT `06` |

不能混用两个通道的响应，也不能只因其他键盘使用相同 VID/PID 就向它发送设置。

无线配置使用32字节 Output Report。最后一字节为前31字节之和的低八位，应答须匹配命令的前三字节。`02` 是链路握手，不是提交或结束命令；设置写入前先验证握手。

| 命令 | 用途 |
| --- | --- |
| `02` | 无线链路握手 |
| `05` | 灯光参数 |
| `07` | 系统参数 |
| `0C` | 校时 |
| `10` / `12` | 普通层 / Fn层改键表 |
| `14` | 逐键 RGB |
| `09` | 宏库 |
| `0B` | 21列、6行高度的音乐频谱 |

批量数据每包最多28字节，含序号和原协议的尾包标记。当前无线菜单按原驱动配置隐藏 TFT 上传和实时逐键帧。

## 验证边界

已实机收到确认的是有线校时、两次实时颜色推送、灯效恢复和 RGB 查询。无线接收器识别正确，但配置握手未收到匹配应答；其余无线功能目前只有静态协议恢复与离线向量检查。

系统写入 API 返回成功不代表键盘接受命令。错误必须保留，不能用空结果、伪应答或放宽匹配来掩盖失败。数据全量替换前应有可靠备份或由使用者明确确认。
